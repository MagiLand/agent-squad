## Changes to act on

The protocol tag is unchanged: `AGENT_SQUAD/0.5.0`. Text that v0.7.0
recorded on the forge still parses.

Both role skills changed, `squad-implementer` and `squad-reviewer`, and they
name commands that v0.7.0 lacks. Upgrade the CLI and the skills together, as
the next section describes.

### Commands that now refuse what v0.7.0 accepted

- `decision post` requires `--recommendation followed|changed|none` on every
  decision except a standing merge instruction or its withdrawal, which take
  neither new option. A general decision (`--finding none`) also requires
  `--kind` with one of `task-approval`, `task-amendment`, `continuation`,
  `budget`, `hold-release`, or `answer`. The CLI writes both values into a
  `Decision record` line after the header and refuses a body that begins
  with such a line. It refuses a kind that contradicts the pull request:
  `continuation` unless the pull request is stopped, `budget` and `answer`
  while it is stopped, `hold-release` unless the latest tagged review
  carries a merge hold, and `task-approval` while the Task is the unreworded
  copy of its issue. Decisions posted before the upgrade carry no record
  line: `status` reports their kind and recommendation as `unknown` and
  keeps them in force.
- `pr merge --accept-merge-hold` refuses unless a `hold-release` decision is
  newer than the latest tagged review. Record the Developer's release first
  with `agent-squad decision post --as implementer --pr <N> --finding none
  --kind hold-release --recommendation <value> --body <file>`. A release
  posted with v0.7.0 has no record line and does not count, so record it
  again before merging a held pull request whose hold was released before
  the upgrade.
- `pr create --task` refuses an `--issue` that is closed or is a pull
  request, as `pr create` without `--task` already did.

### New commands and options

- `pr checks --pr <N> [--wait <seconds>] [--merge-commit] --json` reads the
  checks at the pull request's head, or with `--merge-commit` at its merge
  commit, and summarizes them as `passed`, `failed`, `pending`, `none`, or
  `unavailable`. `--wait` repeats the read while the summary is `pending` or
  `none`, for at most that many seconds, and stops early when the head
  changes. `status --pr <N> --json` reports the reading at the head as
  `ci`. The CLI never refuses a merge because of a check result.
- `pr create --partial`, which requires `--task`, opens a pull request that
  delivers part of an issue: its body ends with `Ref #<N>` instead of
  `Closes #<N>`, so merging it leaves the issue open. While a pull request
  is partial, `pr create`, `pr report`, and `decision post --task` refuse
  text in which a closing keyword such as `Fixes` precedes `#<N>`. `status`,
  `pr merge`, and `pr cleanup` report `closes_issue`.
- `issue list [--milestone <title>] [--label <name>]...
  [--state open|closed|all] --json` lists issues. For each closed issue,
  `closed_by` names the merged pull requests the forge links to it as
  closing it, and is `null` when those links are unknown. `issue view` now
  also reports the issue's `milestone`, `blocks`, and `blocked_by`.
- `issue label --as implementer --issue <N> [--add <label>]...
  [--remove <label>]...` changes an issue's labels. It never removes
  `needs-triage`, `needs-info`, `ready-for-human`, or `wontfix`.

### Event recording, on by default

Every `agent-squad` run now appends one event to a file under
`$XDG_STATE_HOME/agent-squad/events/`, or `~/.local/state/agent-squad/events/`
when that variable is unset, empty, or a relative path. An event stores no
title, body, path, branch, account name, or commit id. To record nothing,
set `AGENT_SQUAD_EVENTS=off` in the environment of every shell and agent
that runs `agent-squad`. `doctor` reports the store in an `event store` row,
and `docs/events.md` describes the fields.

### What the agents now do differently

- The Implementer waits for the head's checks with `pr checks --wait` before
  every `reviewer launch`, never launches a Reviewer for a head whose checks
  failed, and reads the run at the merge commit with
  `pr checks --merge-commit` on both forges.
- The Implementer names one recommended option whenever it asks the
  Developer to decide, records an approved drafted Task as a
  `task-approval` decision and a released hold as a `hold-release`
  decision, and delivers an issue in stages with `--partial` when the issue
  or the Developer asks for it.
- After a merge the Implementer changes labels with `issue label` only when
  the repository documents an issue-closing rule. A repository that wants
  the readiness label removed from a closed issue, or its unblocked
  dependents marked ready, documents that rule.
- The Reviewer lists every check at the head in its evidence and does not
  approve while a check at the head has failed. Missing, pending, or
  unavailable check results are no reason for it to stop.

## Upgrade

Upgrade the CLI and the skills together, because a newer skill names
commands that an older CLI lacks. Install the tag into the environment that
holds the current installation:

```bash
python -m pip install --force-reinstall \
  "agent-squad @ git+https://github.com/MagiLand/agent-squad@v0.8.0"
```

For an installation made with `uv tool`, use this command instead:

```bash
uv tool install --force \
  "agent-squad @ git+https://github.com/MagiLand/agent-squad@v0.8.0"
```

Then install the skills and check the result:

```bash
agent-squad --version
agent-squad skill install
```

`agent-squad --version` prints `0.8.0`. `skill install` refuses to replace
an installed skill that differs from the packaged one; both skills changed in
this release, so it refuses each skill installed from v0.7.0. Compare each
refused skill with the release's copy, in a checkout of this repository that
has the tag:

```bash
git show "v0.8.0:src/agent_squad/skills/squad-implementer/SKILL.md" |
  diff ~/.agents/skills/squad-implementer/SKILL.md -
git show "v0.8.0:src/agent_squad/skills/squad-reviewer/SKILL.md" |
  diff ~/.agents/skills/squad-reviewer/SKILL.md -
```

When the only differences are the release's own changes, run
`agent-squad skill install --force`. Agents read their skills when a session
starts, so start a new session for each running Implementer agent. Finally
run `agent-squad doctor` in the primary checkout of each repository that
uses Agent Squad; it also checks that the installed skills match the
installed package.

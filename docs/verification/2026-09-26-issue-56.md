## Defects found and fixed

- The old data constructors and test patch targets coupled shared logic to the concrete adapter. Parsers now live in `github.py`; neutral records have no wire parsers. Test-boundary adjustments retain their assertions under the Developer's clarification.
- Neutralizing internal review states would otherwise change existing JSON and diagnostics. Adapter-supplied display labels preserve the output while approval checks use the actual neutral state and separate dismissal flag. Tests verify that display labels cannot confer or remove approval.
- The requested 70-command historical count was already stale on main. Both original runs are recorded above; the candidate preserves main's 79-command scenario.

The first doctor attempt was blocked by sandbox restrictions on Git metadata, network, credential-store access, and the Herdr socket. Retrying the same check with normal access passed. An initial scratch comparison used a relative import path in a temporary fixture and failed before comparison; resolving the baseline path fixed the probe. Initial slow test processes were interrupted and restarted with the direct Python interpreter directory on `PATH`; interrupted runs are not passing evidence.

## Scope and limitations

- Standard library only; package version and protocol tag remain 0.5.0. No new command, flag, identity mode, transport, or token configuration is added.
- `forge.kind=forgejo` validates but construction exits 1 with exactly `forge.kind forgejo is not implemented until Increment 3`.
- `approvals()` is tested independently and is not called by the current loop. It includes every author, skips ordinary comment/pending reviews, and recovers dismissed review states by review ID from the documented [GitHub dismissal event](https://docs.github.com/en/rest/using-the-rest-api/issue-event-types#review_dismissed). Missing or conflicting needed history fails validation. The record retains the review's author, commit, and submission time; the dismissal actor is not treated as its author. This new method has deterministic mocked transport coverage, not a real dismissal exercise.
- Unsupported capabilities are exercised with protocol stubs: resolution exits 1 before reads or writes, unreadable resolution is `null`, and unreadable rules report `not visible` without querying them. Existing fake-gh integration cases exercise the supported paths, pending drafts, fallback/resume, branch rules, and selected identity on every mutation.
- Review-before-merge holds apply conservatively: item 1, because credential/identity transport and response parsing move into the adapter; item 3, because the refactor touches the approval-state checks and capability gates on which subsequent reviews and merges rely. The Developer must review and explicitly instruct the merge after the independent review.

## Defects found and fixed

Previously init always wrote the GitHub forge, configuration loading did not
check both token files, and single-mode Doctor omitted the dual-only checks
without a reason. Initialization now validates local configuration and both
files before any Git network operation or API read. Doctor exits on invalid
configuration before contacting either forge identity. Existing validators
still recheck the selected token at each transport read.

Tests cover invalid URLs and role/mode combinations, wrong permissions and
contents, worktree/control-root paths, symlinks and relative token paths,
normalization with an instance prefix, missing flags, no overwrite, linked
worktrees, exact authenticated request roles, absent gh, versions, identity
mismatch, missing repositories/approvers, permission failures, and retained
closed/merged orphan resources.

## Scope and limitations

The live evidence covers setup and diagnostics on Forgejo 16.0.3 only. It does
not establish a full dual-mode review loop, release trials, TLS/SSH setup,
branch-protection approval behavior, or other server versions. Minimum
16.0.0 support and negative cases are verified against the fake server.
Git uses the configured origin independently of the explicit API base URL;
there is no API-host inference or credential forwarding to the Git host.
Doctor performs its existing temporary filesystem/Git probes but does not
repair configuration or delete orphaned resources. `--live-reviewer` is
unchanged and was not exercised against real models for this issue.

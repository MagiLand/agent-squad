## Defects found and fixed

- A new review request with an exhausted budget derives `needs_decision`.
  The initial Reviewer draft classified it as duplicate delivery before the
  budget guard. The guard now runs before that classification; a duplicate
  completed approval is still left alone.
- A same-head Task amendment can lead to two reviews with identical headers.
  Interrupted publication recovery now identifies the particular forge review
  ID, excluding reviews present before publication. An old identical header
  cannot stand in for the new publication.
- The Task-amendment route now explicitly closes the finished Reviewer before
  launching a fresh one, including when the head has not changed.
- The Reviewer frontmatter initially used angle-bracket placeholders that the
  skill validator rejects. Its description now names those fields in prose.
- YAML treated the unquoted `#N` in the Implementer description as a comment,
  truncating its discovery text. Quoting the complete scalar preserves the
  issue trigger and both resume triggers; a before/after YAML parse verified it.
- The trial's first `issue view` failed to resolve the configured account token
  inside the Codex sandbox. The unchanged CLI command succeeded through normal
  per-command escalation, confirming credential-store access as the boundary.
  Both skills now cover that recovery: retry the CLI itself once with escalated
  permission, never read credentials directly, and stop on a failed escalation.
  No credential, account configuration, or sandbox policy was changed.

The CLI exposes configured primary, worktree, and scratch paths through its
read interface so the skills need neither configuration-file reads nor direct
`gh` calls. `pr create` records the designated implementation worktree in its
linked Git administrative directory. This follows the resource-ownership
approach introduced in issue #43: the record binds checkout identity and the
PR, and stores no review, verdict, budget, decision, or handoff status.

Merge reads visible branch protections and rules, passes the approved head to
GitHub, and verifies fetched integration before cleanup. The adapter follows
the documented [merge endpoint](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request)
and [branch-protection endpoint](https://docs.github.com/en/rest/branches/branch-protection#get-branch-protection).
A plan that does not expose branch rules is reported as `no rule visible`;
authentication and rate-limit failures remain errors.

## Scope and limitations

Automated forge reviews, findings, decisions, stops, and Herdr process states
are scripted. The fake forge performs real Git merges in disposable clones.
The smoke exercises moved-base refusal, explicit acceptance with ancestry
verification, and a second PR squash-merged on an unmoved base with tree
identity verification. It verifies that the base checkout stays unchanged.
Publication-recovery smoke cases use an independent disposable PR after the
two successful merges so they cannot invalidate those completed approvals.

A squash after accepting a moved base is reported as `integration not
verifiable by tree identity`, returns exit 1, and retains resources. A failed
cleanup step returns exit 3 and reports its completed and failed steps.
Uncommitted implementation files, mismatched ownership, unowned review
worktrees, and a symlinked scratch directory are retained.

The real trial exercised approval, a human-answered trust dialog, adoption,
explicit merge authorization, ancestry verification, and successful cleanup.
It did not exercise real blocking findings, decisions, stops, or lost delivery;
those paths remain scripted in this increment's deterministic suite. Doctor
feature changes, the README rewrite, the version bump,
both-direction trials, the consumer trial, and rebase merging remain outside
this increment. Agent Squad's own PR uses the manual review pipeline.

## Defects found and fixed

The release smoke previously ran GitHub only. The shared twelve-step workflow
now runs GitHub dual and Forgejo single, including human approval/veto,
unsupported resolution, pending-draft refusal and discard, empty-diff-hunk
recovery, interrupted resume, merge/squash checks and tracking-ref absence.
The existing GitHub single-mode regression remains. Failure cleanup is tested
for both fixture types. Protocol version is now declared independently of the
package version and the release audit inspects both distribution formats.

The VPS trial exposed a reproducible startup-contract mismatch between Agent
Squad's Codex initial-prompt delivery and Herdr 0.9.1. Both later Reviewers
started executing tool calls before Herdr's 30-second startup deadline, yet
`reviewer launch` returned `timeout`. Each independently published its review;
no duplicate `adopt` request was sent. Cleanup then refused with
"the Reviewer pane has a different occupant". The Developer closed the affected
panes before guarded CLI cleanup completed.

A deterministic Unix-socket fixture exercises the installed Herdr CLI without
real models. With the same name, kind, pane and terminal, an agent continuously
reported as `working` makes `herdr agent start ... --timeout 4000 -- <task>`
return the same timeout. Changing only the state to `idle` with interactive
readiness returns success; `blocked` returns `agent_not_ready`. The reproduction
asserting startup success is red. This is distinct from the earlier folder-trust
failure investigated in issue #53.

Inspection of official Herdr 0.9.1 source at
`065ef9d6a531c49fb8bee7e818ef837065b21ee9` confirms that
`src/cli/agent.rs::wait_for_named_agent` keeps waiting while the agent is
working. `src/terminal/state.rs::reconcile_managed_agent_at` clears a pending
agent's registered name at the deadline unless it reached the accepted ready
state. That mechanism explains both observed symptoms, although no historical
snapshot of the cleared name was retained. Agent Squad's occupant check is
correct to preserve resources when the name does not match.

The minimum remedy belongs at the Herdr startup/readiness boundary: a supported
initial task must establish ownership without requiring task completion. Agent
Squad must also cover a long-running initial task in delivery verification.
Blind timeout retries, duplicate request delivery, and weaker cleanup identity
checks are not remedies. Switching to after-start prompting requires new live
evidence: the issue #43 experiment found that route did not execute the Codex
request. Source inspection of Herdr 0.9.2 shows a Codex unknown-state readiness
change but still waits on `working`; it does not establish a fix for this case.
The private diagnostic archive includes the reproduction, three state controls,
and source provenance. Its SHA-256 is
`d535fd59d3440c5092e00f4cb8204b2ace66c992ea141f088ac9e48c3c1bb351`;
a durable copy was verified. Neither Herdr nor Agent Squad was upgraded. The defect remains unresolved;
this record does not claim a passing regression or a corrected launch.

Provisioning encountered
operator prerequisites: unlocking the existing SSH key, correcting DNS, and
opening the required application ports in the host/provider firewalls. The
initial bootstrap script also incorrectly compared the compatibility-suffixed
server version as an exact package version; account/repository state was
inspected before resuming the missing setup steps. These are provisioning
observations, not passing trials or established Agent Squad defects. The existing Doctor
connectivity, identity and token-file checks pass after setup; no new product
misconfiguration diagnostic was needed for these provisioning steps.

## Scope and limitations

The Developer approved a trial-method amendment: Agent Squad must refuse
locally before human approval; a separate disposable probe PR tests the
Forgejo merge API refusal under branch protection. A faulty protection rule
may merge only that probe, in which case the trial stops. The real trial PR
still requires exact-head agent/human approval and explicit Developer merge
instruction. This avoids claiming a server refusal when the CLI correctly
blocks the request before any merge API call. No approval guard changes.

Deterministic proofs use scripted reviews and human decisions, fake Herdr,
private temporary Git repositories, and a loopback fake HTTP server. They are
not live release trials. The existing CI layout already places ordinary smoke
in the PR group and duplicate source-export smoke in main/nightly; no actions,
permissions, triggers, dependencies, or configuration fields change here.

## Defects found and fixed

The README and workflow guide still described Increment 1, and package metadata
still reported `0.4.4`. They now describe the implemented PR loop and version.
The existing smoke already exercised most mechanics. It now publishes twelve
explicit successful steps and asserts finding-text durability, review identity
after recovery, exact approval/invalidation, and temporary-root cleanup.
Failure to remove a fixture reports its retained root; deterministic tests
exercise both ordinary command failure cleanup and failed removal.

Release coverage compares the installed command tree with the approved table
and checks version metadata in both the wheel and source distribution.
Initial test development used the wrong PR body field and an incorrect command
count; inspecting the actual schema corrected these assertions. These were
test-authoring mistakes, not defects in the runtime.

The expanded source-export smoke exceeded its inherited 180-second test
timeout on this host. The subprocess limit is now 300 seconds; the focused
rerun completed successfully in 250.173 seconds. Its fixtures now use the
export directory as `TMPDIR`, so the owning test also removes them if the
runner times out before ordinary cleanup. Both CI jobs passed the corrected
revision, including all 185 tests on each platform.

A manual Herdr start rejected the initial multiline Task prompt before
creating an agent. Retrying with a single-line initial prompt succeeded.
This was a setup command usage error; the product already sends fixed
single-line Reviewer requests, and doctor cannot validate a future manually
entered Implementer prompt.

The later Git SSH failures exposed an unavailable signing key in the
configured SSH agent. Read-only diagnostics found that `github-magiland`
selects the GitHub identity through the 1Password agent, which reported no
identities, while the refreshed macOS agent held a different server-login
key. A targeted trace showed GitHub accepting the configured public key
before authentication failed. No private key, credential, remote, forge
identity, or global configuration was changed by an agent. The initial
successful recheck did not establish a lasting repair; the later recurrence
and failed Task B clone are retained as limitations.

Doctor already exercises this transport through its `remote base branch`
check. `test_trial_issue42_remote_transport_failure_is_reported` verifies a
remote read failure is reported while forge authentication remains distinct
and the origin is preserved. No new runtime mechanism is needed to replace
that diagnostic or to bypass the human-controlled key availability.

## Scope and limitations

The deterministic suite uses fake GitHub/Herdr executables, isolated Git
repositories, and scripted skills and reviews. It establishes mechanics,
not model judgment or real notification delivery. The exported-source smoke
runs without `.git`. All generated evidence remains outside tracked runtime
paths. No new feature, configuration field, dependency, CI orchestration, or
automatic cleanup service is introduced.

Agent Squad's own PR uses the manual review pipeline. Correctness CI on its
exact full HEAD remains a separate gate before each manual Reviewer handoff.
Task A and the consumer trial are complete, including actual decision,
continuation, and notification recovery. The reverse direction is pending
SSH repair, so release acceptance is not claimed.

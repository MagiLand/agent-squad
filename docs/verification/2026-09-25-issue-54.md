## Scope and limitations

This covers exactly Forgejo 16.0.3 with SQLite, a private repository, one
required approval, and the recorded settings. It does not verify other
versions, the client's instance, TLS/SSH transport, performance, pagination
limits, Forgejo Actions, the future adapter, or the future fake server.
The driver used real Git pushes and HTTP writes; browser draft creation was
real UI interaction. Browser form payloads/responses are not saved as JSON;
their server-log status and visible outcome are recorded above. The committed
API envelopes retain every response in the scripted sequence, including
errors, and omit all headers/cookies.

Tokens, email values, and URL authorities were scrubbed. Usernames, IDs,
timestamps, commit IDs, diff text, array ordering, and protocol fields are
preserved. The redacted SSH URLs are not reusable remote URLs. Scrubbed
recordings, rather than private logs or `.local/` research, are the project
inputs. New runs are not byte-identical: commit IDs, IDs, times, and ordering
can vary. Two safe preflight repository GETs were added after this run, so
regeneration includes those extra setup responses. Tests execute no network,
container, or real model.

No claim about the actual integration tree is made for PR 1; see E9. No
attempt was made to diagnose or fix the server's internal behavior. Comment
ordering was sampled three times, not proven randomized or stable. Branch
protection's stale-approval behavior was not independently isolated from
the superseding request-changes review.

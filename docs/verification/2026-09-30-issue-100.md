## Defects found and fixed

The original fake reported successful startup even when the selected state
was still working. It now models idle success, blocked `agent_not_ready`
with the name retained, and working/unknown startup timeout with name removal
and the agent left in its pane. Tests also cover genuine startup failure.

With the corrected fake, the original Codex initial-prompt delivery times
out. Route A fixes the deterministic regression, preserves start arguments,
delivers one request after startup, and permits the unchanged guarded close.
Blocked and prompt-failure coverage runs for both harness kinds.

The first live attempt additionally exposed a folder-trust prompt classified
by Herdr as `unknown`. This is a startup/trust prerequisite, outside this
issue's delivery fix. No detection rules, trust settings, or ownership guards
were changed to bypass it.

## Scope and limitations

Automated checks use fake processes and call no models. Their persistent
working state models exceeding the startup deadline without sleeping. They
do not prove real Codex request delivery or long-running ownership.

The supervised trial proves those behaviors on Herdr client/server 0.9.3
and Codex CLI 0.159.2, after human folder-trust setup. It does not establish
a minimum Herdr version: 0.9.2 was not tested, and route A was not tested on
server 0.9.1 in this run. No doctor version gate was added. Exact submitted-head
CI evidence belongs in the implementation PR report. The primary loop runtime
and merged issue #61 evidence are unchanged.
